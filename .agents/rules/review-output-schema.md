# 📋 Review Output Schema & Formatting Contract

This rule specifies the exact JSON and Markdown output contracts required for review findings to ensure seamless interoperability between specialist agents, the Synthesizer, and GitHub PR comments.

---

## 📦 1. Raw Specialist Finding JSON Schema

Each specialist agent MUST return ONLY a valid JSON array matching this schema:

```json
[
  {
    "severity": "CRITICAL | HIGH | MEDIUM | LOW | INFO",
    "category": "security | performance | style | test-coverage",
    "filePath": "src/main/java/com/example/service/UserService.java",
    "lineNumber": 24,
    "message": "Concise 1-2 sentence description explaining the root cause and risk.",
    "suggestion": "Concrete code replacement snippet or actionable fix."
  }
]
```

### Constraints:
- `lineNumber` MUST be an integer representing a modified, added, or deleted line within the PR diff hunk. Set to `null` ONLY if the finding applies to the file as a whole.
- Do NOT wrap JSON in Markdown code fences (e.g. ` ```json `) when generating raw responses from prompt calls.

---

## 📑 2. Synthesized PR Markdown Report Contract

The final synthesized comment posted to GitHub PRs follows this standardized Markdown format:

```markdown
## 🤖 AI Code Review

### Summary
<1-2 sentences summarizing overall PR quality, architectural impact, and major risks>

### Findings

| Severity | File | Line | Category | Issue |
|---|---|:---:|---|---|
| 🔴 CRITICAL | `UserService.java` | 24 | security | Unescaped string concatenation leads to SQL Injection |
| 🟠 HIGH | `OrderService.java` | 35 | performance | N+1 database queries inside stream loop |

### Suggestions

**`src/main/java/com/example/service/UserService.java`**
- *Line 24*: Use parameterized SQL query placeholders instead of raw string concatenation:
```java
String sql = "SELECT * FROM users WHERE username = ?";
return jdbcTemplate.queryForObject(sql, mapper, username);
```

---
*Review generated by Code Review Orchestrator*
```
