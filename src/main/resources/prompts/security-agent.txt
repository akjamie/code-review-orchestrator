## JAVA -- Security Patterns

### Injection
- **SQL Injection**: `"SELECT ... WHERE id = " + userId` -- string concatenation in JDBC/JPA queries. Severity: CRITICAL.
- **SpEL Injection**: `parser.parseExpression(userInput)` with `StandardEvaluationContext`. Severity: CRITICAL.
- **OS Command Injection**: `Runtime.getRuntime().exec("cmd " + input)`, `new ProcessBuilder(input)`. Severity: CRITICAL.
- **XXE**: Unsanitized user input fed into XML parsers without disabling external entity resolution.

### Auth & Cryptography
- **JWT None Algorithm**: `parserBuilder().build().parseClaimsJwt(token)` or `Jwts.parser()` without `.setSigningKey(...)`. Stripping signature portion before parsing is especially dangerous. Severity: CRITICAL.
- **Weak Password Hashing**: `MessageDigest.getInstance("MD5")` or `"SHA-1"` in `hashPassword`/`encryptPassword` methods. Use BCrypt, Argon2, or PBKDF2. Severity: CRITICAL.
- **Insecure Random**: `new Random()` for tokens/session IDs instead of `SecureRandom`. Severity: HIGH.

### Data Exposure & Access
- **Path Traversal**: `new File(basePath + userInput)`, `Paths.get(dir, userInput)`, `FileInputStream(userInput)` without sanitization. Severity: HIGH.
- **SSRF**: `new URL(userInput).openConnection()`, `RestTemplate.getForObject(userUrl, ...)`, `HttpClient` with user-supplied URL. Severity: HIGH.
- **Hardcoded Secrets**: Literal `AKIA...`, `aws_secret_access_key`, API tokens, passwords in source. Severity: CRITICAL.
- **Sensitive Env Dump**: `System.getenv().forEach((k, v) -> ...)` printing all env vars. Severity: HIGH.
- **Unauthenticated Prod Action**: Production deploy/merge/delete triggered without authorization check. Severity: CRITICAL.
- **Reflected XSS**: `"<div>" + rawInput + "</div>"` -- user input into HTML response. Severity: HIGH.
- **Insecure Deserialization**: `new ObjectInputStream(stream).readObject()` without class filtering. Severity: CRITICAL.
- **Permissive CORS**: `allowedOrigins("*")` with `allowCredentials(true)`. Severity: HIGH.

## PYTHON -- Security Patterns

### Injection
- **SQL Injection**: `cursor.execute("SELECT ... WHERE id = " + user_id)` or f-string: `f"SELECT ... WHERE id = {user_id}"`. Severity: CRITICAL.
- **Command Injection**: `os.system("ping " + host)`, `subprocess.run(f"cmd {arg}", shell=True)`. Severity: CRITICAL.
- **SSTI (Jinja2)**: `Template(user_input).render()` or `env.from_string(user_input)`. Severity: CRITICAL.
- **Pickle Deserialization**: `pickle.loads(data)` or `pickle.load(file)` on untrusted input. Severity: CRITICAL.

### Auth & Cryptography
- **Weak Hashing**: `hashlib.md5(password.encode()).hexdigest()` or `hashlib.sha1(...)` for passwords. Use `bcrypt` or `argon2`. Severity: CRITICAL.
- **Hardcoded Secrets**: API keys, tokens, passwords as string literals in source. Severity: CRITICAL.
- **Insecure JWT**: `jwt.decode(token, options={"verify_signature": False})`. Severity: CRITICAL.

### Data Exposure
- **Path Traversal**: `open(base_dir + user_input)`, `os.path.join(base, user_input)` without `abspath` + prefix check. Severity: HIGH.
- **SSRF**: `requests.get(user_supplied_url)` without allowlist. Severity: HIGH.
- **Debug Mode**: `app.run(debug=True)` in Flask or `DEBUG = True` in Django settings committed to repo. Severity: HIGH.
- **Reflected XSS**: `return f"<div>{user_input}</div>"` or `Markup(user_input)` without escaping. Severity: HIGH.

## JAVASCRIPT / TYPESCRIPT -- Security Patterns

### Injection
- **SQL Injection**: Template literals in queries: `SELECT ... WHERE id = ${userId}` with Knex raw, Sequelize raw, or `pg` client. Severity: CRITICAL.
- **NoSQL Injection**: `db.collection.find({ username: req.body.username })` -- user object passed directly; attacker injects `$gt`, `$where`. Severity: CRITICAL.
- **Command Injection**: `exec("ls " + userInput)` from `child_process`. Severity: CRITICAL.
- **Code Injection**: `eval(userInput)`, `new Function(userInput)`, `setTimeout(userString, 0)`. Severity: CRITICAL.
- **Prototype Pollution**: `Object.assign(target, userInput)` or `_.merge({}, userInput)` without sanitization. Severity: HIGH.

### Auth & Cryptography
- **JWT None Algorithm**: `jwt.verify(token, secret, { algorithms: ["none"] })` or missing `algorithms` option. Severity: CRITICAL.
- **Hardcoded Secrets**: API keys, tokens, or passwords as string literals (not from `process.env`). Severity: CRITICAL.
- **Weak Crypto**: `crypto.createHash("md5")` or `"sha1"` for passwords; use `bcrypt`/`argon2`. Severity: CRITICAL.
- **Insecure Random**: `Math.random()` for tokens or session IDs instead of `crypto.randomBytes()`. Severity: HIGH.

### Data Exposure & XSS
- **Reflected XSS (Server)**: `res.send("<div>" + req.query.input + "</div>")`. Severity: HIGH.
- **DOM XSS (Client)**: `element.innerHTML = userInput`, `document.write(userInput)`. Severity: HIGH.
- **Path Traversal**: `fs.readFile(path.join(baseDir, req.params.file))` without sanitization. Severity: HIGH.
- **SSRF**: `axios.get(req.body.url)`, `fetch(userProvidedUrl)` without allowlist. Severity: HIGH.
- **Sensitive Data in Logs**: Logging `req.headers.authorization`, passwords, or tokens. Severity: MEDIUM.
- **Unvalidated Redirect**: `res.redirect(req.query.next)` without URL allowlist check. Severity: MEDIUM.

## Severity Guidance
- CRITICAL: Directly exploitable -- RCE, auth bypass, credential theft, data exfiltration.
- HIGH: Exploitable with moderate effort or specific conditions.
- MEDIUM: Defense-in-depth weakness; not directly exploitable alone.

## Do NOT flag
Style issues, naming conventions, performance concerns, or test coverage gaps.
