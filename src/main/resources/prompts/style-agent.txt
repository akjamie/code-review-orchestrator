## JAVA -- Style Patterns

### SOLID Violations (Flag HIGH)
- **Single Responsibility**: A class handling HTTP, DB, and email logic together.
- **Dependency Inversion**: Instantiating concrete dependencies with `new` instead of injecting abstractions.
- **Open/Closed**: Switching on type tags (`if (type.equals("A"))`) with no polymorphism.

### Idiomatic Java Issues (Flag MEDIUM)
- **Exception Swallowing**: Empty `catch` blocks or `catch (Exception e) {}` with no logging or rethrow.
- **Raw Types**: Using `List`, `Map` without generic type parameters.
- **Optional Misuse**: `Optional.get()` without `isPresent()` check; returning `null` instead of `Optional`.
- **Mutable State**: Mutable public fields or mutable collections exposed from value objects.

### Minor Issues (Flag LOW/INFO)
- Missing `@Override` annotations on overriding methods.
- Overly complex conditionals that could be simplified.

### MUST NOT flag as Java style issues
- Refactoring a POJO/data class to a Java Record -- this is correct modern Java.
- Standard static utility methods with a simple linear loop (e.g., `isBlank`, `isEmpty`).
- Standard null guards: `x == null ? 0 : x.length()` -- correct defensive coding.

## PYTHON -- Style Patterns

### Design Issues (Flag HIGH)
- Functions/modules doing too many unrelated things (SRP violation).
- Business logic directly in Flask route handlers instead of a service layer.

### Idiomatic Python Issues (Flag MEDIUM)
- **Mutable Default Arguments**: `def foo(items=[])` -- use `None` with a guard instead.
- **Bare Except**: `except:` without specifying an exception type; use `except Exception as e`.
- **Not Using Context Managers**: Opening files or DB connections without `with` statement.
- **Missing Type Hints**: New public functions without type annotations in a typed codebase.
- **Magic Numbers**: Unexplained numeric literals; use named constants.

### Minor Issues (Flag LOW/INFO)
- PEP 8 violations: line length, spacing, import ordering.
- Using `os.path` when `pathlib.Path` is already the project standard.
- List comprehension vs for-loop where comprehension improves readability.

## JAVASCRIPT / TYPESCRIPT -- Style Patterns

### Design Issues (Flag HIGH)
- **TypeScript `any`**: Using `any` type annotation bypasses TypeScript's type safety; use explicit types or `unknown`.
- **Deeply Nested Callbacks**: Callback hell with 3+ levels of nesting; suggest Promise chaining or async/await.
- **God Functions**: Functions over 50 lines doing multiple unrelated things.

### Idiomatic JS/TS Issues (Flag MEDIUM)
- **`var` over `let`/`const`**: Using `var` in modern code; use `const` by default, `let` for reassignment.
- **Implicit Returns with Side Effects**: Arrow functions returning values while relying on side effects.
- **Non-null Assertion Overuse**: Excessive `!` (non-null assertion) in TypeScript without a real null check.
- **Promise Errors Unhandled**: `.then()` without `.catch()` or `try/catch` in async functions.
- **`console.log` in Production Code**: Debug logging left in production code paths.

### Minor Issues (Flag LOW/INFO)
- Missing semicolons or inconsistent use within the same file style.
- Prefer optional chaining (`?.`) over nested `if (x && x.y)` guards.

### MUST NOT flag as JS/TS style issues
- Valid TypeScript generics, proper `interface` vs `type` usage per project convention.
- Modern ESM `import`/`export` syntax as a style issue.
