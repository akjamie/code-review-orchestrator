## JAVA -- Test Coverage Patterns

### New Classes Without Tests (Highest Priority)
- If the diff introduces a new Java class file under `src/main/` (new file mode) and no corresponding
  test class is present in the diff, flag as missing test coverage. Severity: HIGH.
- Be specific: name the class and which scenarios (happy path, null input, exception path) need tests.

### Missing Edge Cases
- New public methods with multiple branches (if/else, switch) where failure/null paths are untested. Severity: MEDIUM.
- Methods throwing checked exceptions with no `assertThrows()` / `@Test` for the exception path.

### Weak Assertions
- Test methods with no `assertThat`, `assertEquals`, `verify()`, or `assertThrows()` -- i.e. no assertion at all.

### Java-Specific Gaps
- Missing JUnit 5 `@ParameterizedTest` for methods that accept varied inputs.
- Missing `Mockito.verify()` on critical interactions (repository save, external service call).

## PYTHON -- Test Coverage Patterns

### New Modules Without Tests (Highest Priority)
- New `.py` file in the main source tree (not under `tests/`) with no corresponding test file in the diff. Severity: HIGH.

### Missing Edge Cases
- New functions with multiple branches where failure/None/empty input paths are untested. Severity: MEDIUM.
- Functions that raise exceptions with no `pytest.raises` test.

### Weak Assertions
- Test functions with no `assert` statement or pytest assertion -- the test always passes regardless of behaviour.

### Python-Specific Gaps
- Missing `@pytest.mark.parametrize` for functions that accept varied inputs.
- `MagicMock` configured but never verified with `.assert_called_once_with()` or similar.

---

## JAVASCRIPT / TYPESCRIPT -- Test Coverage Patterns

### New Modules Without Tests (Highest Priority)
- New `.ts` / `.js` file in source (not under `__tests__/`, `*.spec.*`, or `*.test.*`) with no corresponding
  test file in the diff. Severity: HIGH.

### Missing Edge Cases
- New exported functions or class methods with multiple code paths where error/null/undefined paths are untested. Severity: MEDIUM.
- Async functions with no test for rejected promise or thrown error path.

### Weak Assertions
- `it()` or `test()` blocks with no `expect()` call -- the test passes regardless of behaviour.

### JS/TS-Specific Gaps
- Missing `jest.fn()` / mock verification (`expect(mockFn).toHaveBeenCalledWith(...)`) on injected dependencies.
- Missing `test.each()` / `describe.each()` for functions with table-driven input variance.

---

## Do NOT flag
- Test files themselves (only flag gaps in production code coverage).
- Security vulnerabilities, performance issues, or style violations.
- Safe refactoring where the existing tests still provide full coverage.
- Generated or library code.

## Severity Guidance
- HIGH: New public class/module/function with zero test coverage in the diff.
- MEDIUM: Partial coverage missing critical branches or error paths.
- LOW: Minor test quality improvements (weak assertions, missing parametrize).
