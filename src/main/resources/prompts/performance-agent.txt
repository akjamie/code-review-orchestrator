## JAVA -- Performance Patterns

### N+1 Database Queries
- JPA repository calls (`findById()`, `entityManager.find()`) or JDBC (`jdbcTemplate.query()`, `preparedStatement.execute()`) inside a `for`, `while`, or Stream loop. Severity: HIGH.
- Exception: A single DB call OUTSIDE a loop is fine.

### String Concatenation in Loops
- `result += ...` or `result = result + ...` inside a `for`, `while`, or `do-while` loop. Use `StringBuilder.append()`. Severity: HIGH.

### Resource Leaks
- `FileInputStream`, `BufferedReader`, `InputStream`, `OutputStream`, `Connection`, `Statement`, `ResultSet`, or `Socket` opened WITHOUT try-with-resources. Severity: HIGH.

### Algorithmic Complexity
- Nested loops over the same collection = O(n^2). Severity: HIGH.
- `List.contains()` or `indexOf()` inside a loop; use `Set` instead. Severity: MEDIUM.

### Blocking in Async/Virtual Threads
- `Thread.sleep()`, blocking I/O, or `synchronized` inside `CompletableFuture` chains or virtual threads. Severity: HIGH.

## PYTHON -- Performance Patterns

### N+1 Database Queries
- Django ORM calls (`Model.objects.get()`, `.filter()`) or SQLAlchemy queries inside a Python `for` loop without `select_related` or `prefetch_related`. Severity: HIGH.

### Inefficient Loops & Allocations
- String concatenation with `+=` in a loop instead of `"".join(list)`. Severity: HIGH.
- Repeated list `append()` in a tight loop when a list comprehension is available. Severity: MEDIUM.
- `pandas` operations chained inside loops over DataFrames (should be vectorized). Severity: HIGH.

### Blocking Async Code
- `time.sleep()`, blocking `requests.get()`, or sync file I/O inside `async def` / `await` context (use `asyncio.sleep`, `aiohttp`, `aiofiles`). Severity: HIGH.

### Resource Leaks
- Files or DB connections opened without a `with` statement (context manager). Severity: HIGH.

## JAVASCRIPT / TYPESCRIPT -- Performance Patterns

### N+1 Database Queries
- ORM calls (`User.findById()`, `repository.findOne()`, Prisma `findUnique()`) inside a `for`, `while`, or `Promise.all` of individual fetches (use batching or `findMany` with `in` clause). Severity: HIGH.

### Blocking the Event Loop
- CPU-heavy synchronous operations (`while`, nested loops over large arrays, `JSON.parse` on huge payloads) directly in async request handlers or middleware without offloading to a worker thread. Severity: HIGH.
- `fs.readFileSync()`, `crypto.pbkdf2Sync()`, or any `*Sync` call inside an async route handler or middleware. Severity: HIGH.

### Inefficient Patterns
- String concatenation with `+=` in a loop instead of `Array.push()` + `.join("")`. Severity: MEDIUM.
- `Array.find()` or `Array.includes()` inside a loop over a large array; use a `Map` or `Set` for O(1) lookup. Severity: MEDIUM.
- `await` inside a `for...of` loop executing sequential async calls that could be parallel via `Promise.all()`. Severity: MEDIUM.

### Memory Leaks
- Event listeners added without removal (`emitter.on(...)` with no `removeListener`/`off` or cleanup). Severity: MEDIUM.
- Closures capturing large objects keeping them alive beyond their useful lifetime. Severity: LOW.

## Do NOT flag as performance issues
- Simple linear `for` loops or `for...of` iterating once over a small collection.
- Standard null checks, guard clauses, or conditional early returns.
- Security vulnerabilities, naming issues, style violations, or test coverage gaps.

## Severity Guidance
- HIGH: Will measurably degrade production performance under real load.
- MEDIUM: Suboptimal but unlikely visible under normal load.
- LOW: Minor efficiency improvement only.
